# Candidate Dataset Review: Open-SWE-Traces

Status: license/provenance review complete. Verdict: proceed to install and
onboard as active Dataset #2, replacing `dialogue-swe-bench`.

This review is metadata/schema-level only. It does not download raw content,
train models, run E1/E2, calibrate anything, change runtime behavior,
implement J-space/Jacobian Lens work, or make consciousness-level claims.

## License

Declared directly in the Hugging Face dataset card's structured
`cardData.license` field and repo tags: **`cc-by-4.0`**. This is stronger
evidence than `dialogue-swe-bench` had — that dataset's license was `null`
everywhere it was checked. Here the license is a first-class structured field
on the source-of-truth API response, not inferred from a paper page.

CC BY 4.0 requires attribution on use; it does not forbid commercial use,
transformation, or training-oriented use. Per-row `license` metadata is also
present in the schema (the upstream issue statements were filtered from
SWE-rebench-V2 to permissive source licenses: MIT, Apache-2.0, BSD-2-Clause,
BSD-3-Clause) — this per-row field should be preserved and checked, not
assumed uniform, during any future conversion.

## Schema (from `cardData.dataset_info.features`)

`instance_id`, `repo`, `license`, `language`, `trajectory_id`,
`trajectory` (list of `{role, content, reasoning_content, think,
tool_calls}`), `tools`, `resolved` (int64), `metadata` (struct:
`category`, `reference_patch{patch, num_modified_files, num_modified_lines}`,
`model_patch{patch, num_modified_files, num_modified_lines}`).

`resolved` is present directly on every row. This is a meaningful advantage
over `swe-gym-openhands-sampled`, where only 491/6,055 (8%) examples carry a
resolved outcome.

## Why This Is A Stronger Fit Than Dialogue SWE-Bench

- License is declared and structured, not `null`.
- Trajectory-shaped (`trajectory`, `tool_calls`, `tools`), so it maps
  directly to `TrajectoryExample` the way `swe-gym-openhands-sampled` does,
  instead of needing new dialogue-shaped example types.
- Dense `resolved` outcome label on every row supports `RISK_PREDICTION`,
  `PATCH_SUCCESS`, and `FAILURE_SHAPE` task types without the sparsity
  problem Dataset #1 has.
- `reference_patch` vs `model_patch` diff gives a natural `VERIFIER_VALUE` /
  `SCAR_MOTIF` signal (does the model patch diverge from the reference, and
  how).

## Caveats

- Trajectories are synthetic: generated by Minimax-M2.5 (`thinking` mode)
  and Qwen3.5-122B-A10B (`non-thinking` mode), not human engineers. Any
  future `label_provenance.kind` for fields derived from this dataset must
  be `constructed_label` or `simulated_label`, never `harness_outcome`, even
  though `resolved` looks like a ground-truth field.
- `resolved` is itself a verifier-style automated outcome over synthetic
  trajectories, not a human-graded judgment. Confidence should be recorded
  as `medium`, not `high`, pending a review of the verifier methodology in
  the paper.
- SWE-rebench-V2 lineage carries the same SWE-bench-family contamination and
  benchmark-leakage class of risk already tracked for
  `swe-gym-openhands-sampled` and `dialogue-swe-bench`. A future converter
  needs the same repo-grouped split discipline as Dataset #1, plus a
  cross-dataset leakage check against repos already used in Dataset #1's
  splits before any joint training use.
- `metadata.reference_patch.patch` and `metadata.model_patch.patch`, plus
  `trajectory[].content`/`tool_calls`, are leakage-sensitive fields (gold
  patch and raw tool-use content) and must be blocked from default input
  payloads by a governance module, the same way
  `src/pneuma_lab/training/dialogue_governance.py` blocks patch/oracle
  fields for Dataset #2.
- The generation pipeline used third-party model outputs (Minimax-M2.5,
  Qwen3.5-122B-A10B). NVIDIA's CC BY 4.0 grant covers the released dataset
  artifact as redistributed; this review did not independently verify
  Minimax's or Qwen's own terms of service regarding training on their
  model outputs. This does not block metadata onboarding or bounded
  non-training conversion, but it should be re-checked before any actual
  training authorization, alongside the CC BY 4.0 attribution requirement.
- No canonical adapter or converter exists yet for this dataset's schema
  shape (parquet trajectory rows, not `PneumaTrace` JSONL). Adapter design
  is future work, not part of this pass.

## Verdict

License/provenance is clear enough to proceed with install and
metadata-only onboarding. This review does not authorize training,
adapter/converter implementation, or bounded real-row conversion — those
remain separate future passes gated by their own readiness checks, per the
same discipline already applied to Dataset #1.
