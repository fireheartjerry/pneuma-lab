# Dataset Onboarding: Open-SWE-Traces

## Status

Onboarded as the active Dataset #2 in metadata-only form, replacing
`dialogue-swe-bench` (archived; see `docs/data/archive/dialogue-swe-bench/`
and `docs/data/candidate-reviews/open-swe-traces.md`). This pass makes the
dataset legible to the registry and installs the raw snapshot plus
metadata-only sidecars; it does not implement an adapter, emit
`PneumaTrainingExample` records, train a model, run E1/E2, calibrate
anything, touch runtime behavior, process SWE-chat, or make
consciousness-level claims.

## Why Selected As Dataset #2

`open-swe-traces` is a large trajectory-shaped SWE-agent dataset (207,489
agentic trajectories across 9 languages) published by NVIDIA on Hugging
Face under a declared, structured `cc-by-4.0` license -- stronger evidence
than `dialogue-swe-bench` ever had (that dataset's license was `null` at
every source checked: local provenance, Hugging Face, and GitHub). See
`docs/data/candidate-reviews/open-swe-traces.md` for the full license and
provenance review.

It is trajectory-shaped (`trajectory`, `tool_calls`, `tools`), so it maps
naturally onto `TrajectoryExample`, the same canonical shape
`swe-gym-openhands-sampled` uses, and carries a dense `resolved` outcome
label on every row (112,002 resolved-true / 95,487 resolved-false), unlike
Dataset #1's 8%-resolved sparsity problem.

## Shape And Labels

Per the Hugging Face dataset card schema: `instance_id`, `repo`, `license`
(per-row source-repo license), `language`, `trajectory_id`, `trajectory`
(list of `{role, content, reasoning_content, think, tool_calls}`), `tools`,
`resolved` (int64), `metadata` (struct: `category`, `reference_patch{patch,
num_modified_files, num_modified_lines}`, `model_patch{...}`).

`resolved` is present on every row (54% true / 46% false), unlike
`dialogue-swe-bench`, which never exposed a canonical `resolved` field at
all.

## Privacy And Provenance Status

Public, HF-hosted benchmark-derived synthetic data. Trajectories were
generated by Minimax-M2.5 and Qwen3.5-122B-A10B over real-world PRs sourced
from SWE-rebench-V2 (filtered to permissive source licenses). No redaction
receipt exists because no canonical processed text outputs or training
examples exist yet -- only metadata sidecars.

## How It Differs From OpenHands Sampled And Dialogue SWE-Bench

OpenHands sampled is an adapter-backed `PneumaTrace` dataset with
deterministic hashes and redaction totals; `open-swe-traces` currently has
metadata sidecars only, the same onboarding stage `dialogue-swe-bench` was
at. Unlike `dialogue-swe-bench`, `open-swe-traces` is trajectory-shaped
(not dialogue-shaped) and carries a dense `resolved` label, so it is
expected to graduate to a `PneumaTrace`-style adapter rather than the
dialogue-specific example types `dialogue-swe-bench` was scoped for.

## Expected Canonical Example Types

- `TrajectoryExample` (primary)
- `PatchExample` (via `metadata.reference_patch` / `metadata.model_patch`)

## Likely Task Types For PneumaBrain-v0

`RISK_PREDICTION`, `FAILURE_SHAPE`, `SCAR_MOTIF`, `PATCH_SUCCESS`, and
`VERIFIER_VALUE` (via the reference-patch vs. model-patch divergence). All
labels derived from this dataset must use `label_provenance.kind` values of
`constructed_label` or `simulated_label` -- the trajectories and their
`resolved` outcomes are synthetic/automated, not human-graded, even though
`resolved` looks like ground truth.

## Allowed Next Steps

- Use the registry manifest for metadata-only onboarding validation.
- Design a `PneumaTrace`-style adapter for the `trajectory`/`tool_calls`
  shape, analogous to `src/pneuma_lab/adapters/openhands_sampled.py`.
- Design a governance module blocking `metadata.reference_patch`,
  `metadata.model_patch`, and raw `trajectory` content from default input
  payloads, analogous to `src/pneuma_lab/training/dialogue_governance.py`.
- Add a cross-dataset leakage check against repos already used in Dataset
  #1's splits before any joint training use (SWE-rebench-V2 lineage
  overlaps the SWE-bench family).

## Blocked Next Steps

- Do not train models in this pass.
- Do not run E1/E2 or calibration in this pass.
- Do not convert rows into `PneumaTrainingExample` records in this pass.
- Do not read, sample, or persist `trajectory`, `tools`, or `metadata`
  (patch) content beyond what this pass already recorded as schema
  metadata.
- Do not process SWE-chat.
- Do not modify runtime behavior.
- Do not implement J-space/Jacobian Lens work.
- Do not make consciousness, interiority, sentience, Level 4/5, or
  moral-patienthood claims.

## Caveats

- Trajectories and `resolved` outcomes are synthetic/automated, not
  human-graded.
- SWE-rebench-V2 lineage carries the same SWE-bench-family contamination
  and benchmark-leakage risk class already tracked for
  `swe-gym-openhands-sampled` and archived `dialogue-swe-bench`.
- Third-party model outputs (Minimax-M2.5, Qwen3.5-122B-A10B) were used to
  generate the trajectories; NVIDIA's CC BY 4.0 grant covers the released
  dataset artifact, but this review did not independently verify Minimax's
  or Qwen's own terms of service regarding training on their model
  outputs. Re-check before any training authorization.
- No canonical adapter or converter exists yet.
- No redaction receipt or adapter report exists yet.
